# Proposed MPE recovery requirements

Status: future-release requirements; **none is claimed implemented by this proposal**. `UDB-MPE-*` IDs describe UmbraDB composition responsibilities, not replacements for MPE protocol obligations.

| ID | Proposed EARS requirement | Acceptance evidence / MPE link |
|---|---|---|
| UDB-MPE-001 | When an MPE processing batch commits, the recovery adapter shall atomically commit its local effects, dedup records, outbox intents, optional checkpoint and cursor. | Kill/fault before every commit boundary; either complete state vector or prior state; MPE-CON-033. |
| UDB-MPE-002 | If a batch repeats an already committed logical action with the same authenticated intent, then the recovery adapter shall return its recorded local result without repeating the local effect. | Duplicate envelopes and alternate-envelope same-action tests; MPE-CON-033/044a/044b; contract replay remains contract-owned. |
| UDB-MPE-003 | If a repeated logical action identifier carries a conflicting authenticated intent, then the recovery adapter shall reject the batch without changing its processing cursor. | Same action ID/different digest negative control; MPE-CON-043 authority context and MPE-CON-033 local idempotency. |
| UDB-MPE-004 | While strict MPE durability is enabled, the recovery adapter shall reject a processing commit whose effective connection policy does not flush WAL locally before acknowledgement. | Unsafe-policy, warning-swallow and reconnect negative controls; MPE-CON-033/MPE-STO-025 recovery; MPE-STO-011 receipt-after-persistence context. Strict power-loss durability is an added local profile gate. |
| UDB-MPE-005 | If writer ownership is lost or stale, then the recovery adapter shall prevent its protected transaction from committing local effects or advancing its cursor. | Kill lease connection while pooled transaction is pending; no stale-owner commit; MPE-CON-033. |
| UDB-MPE-006 | When restoring an MPE recovery bundle, the recovery adapter shall authenticate its domain, profile, checkpoint/cursor binding and required trusted freshness evidence before accepting state. | Corruption, cross-network/principal/profile and stale-backup negative controls; MPE-STO-025 and recovery profile. |
| UDB-MPE-007 | Where secret-bearing recovery state is enabled, the recovery adapter shall persist it only through the selected authenticated encryption and endpoint key-custody profile. | Database/WAL/backup fixture inspection, wrong-key/rotation failure and no-plaintext-fallback tests; MPE-PRV-007 endpoint custody and selected encryption profile. |
| UDB-MPE-008 | Where an erasure-sensitive session profile is enabled, the recovery adapter shall reject a history policy that retains obsolete session secrets beyond that profile's permitted erasure horizon. | Checkpoint/TemporalKV history/backup policy tests; MPE-CRY-029/030 key erasure and MPE-PRD-016 backup profile. |
| UDB-MPE-009 | If required retained state, recovery keys or freshness evidence is unavailable, then the recovery adapter shall report a typed blocked restore or history gap without silently advancing or resetting its cursor. | Pruning, missing-key and absent-evidence tests; MPE-STO-025. |
| UDB-MPE-010 | When pruning MPE recovery data, the recovery adapter shall preserve every live manifest dependency and dedup record required by the declared replay policy. | Load-under-prune and replay-after-prune tests; MPE-STO-025/MPE-CON-033 and explicit local replay policy. |
| UDB-MPE-011 | When dispatching a committed outbox intent, the recovery adapter shall preserve its destination idempotency key and explicit uncertain-completion state, and refuse dispatch after its expiry. | Lost remote reply, expiry and replay tests; MPE-PRD-005/009; no remote exactly-once claim. |
| UDB-MPE-012 | When restoring chain-derived processing state, the recovery adapter shall preserve its verified source identity and finality status supplied by the caller. | Provisional/failed/retracted/final source fixtures; MPE-CON-058/059; origin validation remains MPE-owned. |
| UDB-MPE-013 | While the strongest MPE privacy profile is selected, the recovery adapter shall refrain from emitting any automatic upstream recognition or processing acknowledgement. | Callback/restore/quarantine network transcript tests; MPE-CON-039. |
| UDB-MPE-014 | The MPE recovery capability shall expose supported root-package interfaces, stable typed errors and required non-skipping recovery tests before its release is accepted. | Package import/type surface and required test-ID gates; extension does not deep-import a SQL resolver. |

The complete schema, cipher suites, anti-rollback trust source, lease-owner protocol and performance envelope are implementation-design decisions still to resolve. These requirements define acceptance, not an existing behavior claim.
