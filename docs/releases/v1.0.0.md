# UmbraDB v1.0.0 — Release Record (PENDING)

**Status: not released. Blocked.**

All twenty gate items G1–G20 are merged and all five `v1.0.0-*` OpenSpec changes are complete. The
per-gate evidence for that work is recorded in [`v0.9.5.md`](v0.9.5.md), which documents the release
that ships this code today.

## What 1.0.0 additionally requires

> A **full local sync of UmbraDB against Midnight** — archive node → local indexer → UmbraDB,
> demonstrated end to end on infrastructure we run, rather than the wallet-scoped sync against the
> hosted indexer that satisfied G12/R5.

This is a deliberate owner tightening of the gate under `docs/v1-implementation-guideline.md` §0.2
("may add conditions … MUST NOT weaken"). The rationale, and the ParityDB arena corruption that had
been silently blocking the local sync, are recorded in `ROADMAP.md` § "What blocks 1.0.0".

## What must happen before this record can be completed

1. The archive node reaches Preprod tip.
2. The local indexer catches up to the archive node.
3. UmbraDB ingests from **that** local stack, end to end, with evidence recorded alongside
   `docs/recovery/EVIDENCE.md`.
4. The tag gate R1–R12 is re-run against the resulting release candidate — including a fresh R5 live
   run and an independent cold R6 audit against that RC, neither inherited from 0.9.5.
5. `package.json` and `package-lock.json` move to `1.0.0`, and the `CHANGELOG` `1.0.0` entry is
   dated.
6. **`.github/workflows/publish.yml` is restored and npm publication actually runs.** It was removed
   for 0.9.5 by owner decision (see `v0.9.5.md` §R7). R7 requires provenance published from CI, and
   that cannot be satisfied from a local machine, so the workflow has to come back before 1.0.0 can
   claim R7.

At that point the SemVer commitments in [`docs/STABILITY.md`](../STABILITY.md) take effect. They do
**not** apply to 0.9.5.
