# UmbraDB v0.9.5 — Release Record

*Gate-evidence artifact in the form required by `docs/v1-implementation-guideline.md` §4.2 **R1**. It
lists each of the twenty gate items G1–G20 with its status, an **evidence pointer**, and an
accountable owner, then records the tag preconditions R1–R12.*

> **Why this is a 0.9.5 record and not the 1.0.0 one.** All twenty gate items are merged and all five
> OpenSpec changes are complete — the evidence below is real and applies to exactly this code. What
> 1.0.0 additionally requires is a **full local sync of UmbraDB against Midnight** (archive node →
> local indexer → UmbraDB), which is not yet done. `0.9.5` therefore ships this code **without** the
> SemVer freeze commitment that 1.0.0 makes. The pending 1.0.0 record is
> [`v1.0.0.md`](v1.0.0.md); see `ROADMAP.md` § "What blocks 1.0.0".

> **R1's binding rule: a gate with no evidence pointer is not green.** "Evidence" means a CI run URL,
> a test id enforced by the required gate, a committed artifact path, or a named auditor verdict —
> never a claim in prose. Where a gate landed in a form different from its original wording, this
> record says so and says what the difference is, rather than ticking it silently.

## 3. Rulings recorded for this release

**Ruling 1 — the Lean cut-line: Option A (close on deferral).** The `formal-completion` analysis
forced a choice: close the "tractable properties proved in Lean" checklist item on the frozen
`{T3,T5,W1,C1}` plus a written deferral (**Option A**), or prove C2a (GC reachability-safety) and L1
(lease mutual-exclusion) into the tag (**Option B**). Option B is permissible only after an explicit
amendment bundle — widening the frozen set at G20/E3/§3.4/R8, extending the closed G1–G20 gate set,
changing the five-change entry criterion to six, and updating the api-surface release-contract spec —
and costs an estimated 1.5–3 further weeks.

**Option A is taken.** It is the guideline's own default path, it is what an audit council of two
Opus 5 lanes plus a GPT-5.6 Sol capstone recommended, and it requires no amendment. The frozen set is
**not** widened. C2a, L1, C2b, multi-key lifting, ordered reconstruction, cross-module composition,
and the full abstract→PostgreSQL refinement are recorded as **not proved** in `ROADMAP.md`'s G20
deferral, each with what enforces it at runtime instead. The proofs become the immediate post-1.0.0
formal workstream, tracked as `openspec/changes/v1.1.0-formal-completion`.

Two honesty points this ruling depends on, both stated in the roadmap rather than left implicit:
`0 sorry` **certifies depth, not breadth** — the trust gate proves that what is stated is proved and
cannot detect a missing or too-weak law; and the deferral had to be *completed* before it could be
relied on, because ROADMAP's original G20 wording omitted C2b and composition, and a law that is
neither proved nor deferred is exactly the overclaim the program forbids.

**Ruling 2 — R7 artifacts were missing and were added, not waived.** The guideline assigns
`.github/workflows/publish.yml` to the infosec-signoff change, but no task encoded it and the file
existed on no branch; `package.json` was also missing `repository` (**required** for provenance —
its absence alone would have failed the publish) and `license` (undefined, despite an Apache-2.0
`LICENSE` file in the tree). Because provenance cannot be generated from a local machine at all, the
alternative to adding these was a recorded drop-ruling. They were added instead, so **no waiver is
needed and R7 is satisfied on its merits.**

**Ruling 3 — G11 landed rescoped.** Recorded above and in `ROADMAP.md`; the rescope is stated as a
rescope, and the negative control exists precisely so the gate cannot pass vacuously.
